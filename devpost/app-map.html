Questify: App Map

A one-page guide to where things live, so you know where to start when you want to change something.

What the app is

Questify is a phone-sized website (a Progressive Web App) with no server and no accounts. You set a goal and up to three daily quests, focus on them by a bonfire, earn coins, and spend them on a shadow army. Miss a deadline and the whole app locks into the Penalty Zone until you submit proof.

It has four main pieces:

  • Rules (js/quests.js, js/rewards.js, js/config.js): plain functions that decide things, such as what counts as missed and how much XP a quest pays.
  • Memory (js/store.js): one saved object in the browser, plus photos in IndexedDB.
  • Screens (index.html, js/screens/, js/penalty.js, js/battleground.js): what you see and tap.
  • Router (js/main.js): shows exactly one screen at a time and enforces the lock.

One action, followed through: missing a quest

Because the "missed" note is saved to storage, closing or reloading the app does not escape the lock.

Reference route (three stops)

1. Decide: js/quests.js → findMissed

For each quest it walks back from today and reports the most recent day whose deadline has passed with no tick. Search for export function findMissed. A week away still gives one penalty per quest, not seven.

2. Remember: js/penalty.js → enforcePenalty

If nothing is pending and findMissed returns a quest, it saves it with update((s) => { s.penalty = missed; }). update lives in js/store.js and writes to localStorage under the key lifeApp.v1.

3. Enforce: js/main.js → go

The first line of go is if (enforcePenalty()) name = 'penalty';. Whatever screen was asked for, a pending penalty wins.

To change this, start here

  • Words on the Penalty Zone screen: render() in js/penalty.js (the weeks caption, "Was due..." line).
  • The 5-second hold for the no-camera fallback: FALLBACK_HOLD_MS, used by startHold in js/penalty.js.
  • Quotes: data/quotes.js.
  • Coins, XP and the level curve: js/config.js.
  • Soldiers, weapons and prices: data/catalog.js.
  • Accent colours: the colour list in js/config.js; the look itself is css/base.css and css/screens.css.
  • How the dark soldiers and demons are drawn: tools/make-sprites.cjs, then run node tools/make-sprites.cjs.
  • Any new file the app loads: also add it to the list in sw.js, or it will not work offline (a rule check in tests/check-logic.mjs catches this).

A practice to reuse

Put each rule in a small function you can test without the screen. The "was this quest missed?" rule is findMissed, a plain function that takes the saved state and a time. Because it does, tests/check-logic.mjs can feed it a time of 20:59 (expects no penalty) and 21:00 (expects one), and also a miss on an earlier day while the app was closed, with no phone and no waiting.

Where it helps on another project: when you ask an agent to build a behaviour, ask it to state the exact observable result ("at 21:00 with no tick, this returns the quest"). That sentence becomes both the instruction and the check, and a wrong guess shows up as a failing line instead of a surprise on your phone.

Run it again

npx serve .
# open http://localhost:3000 in a browser at phone size

node tests/check-logic.mjs   # rule checks, no browser needed
